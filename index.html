JumpServer setup guide

Install JumpServer on your own machine, prove it works, then repeat on a stage and production server. Each part ends with a check, so you always know it worked before moving on.

Before you start

Same requirements everywhere. Local, stage and production only differ in size, address and security.

ItemMinimumNotes
OSLinux x86_64Ubuntu 22.04/24.04 recommended. On Windows use WSL2 or a VM; on macOS use a Linux VM.
CPU / RAM / Disk4 cores / 8 GB / 60 GBProduction: 8 GB+ RAM and a larger disk for session recordings.
SoftwareDocker + curlThe installer can install Docker for you.
Ports80, 443, 22222222 is the SSH gateway. Database proxy ports (e.g. 27017 for MongoDB) are opened later, only if needed.
Use three separate installs. Never reuse the local or stage database, secret key or admin password for production.

Part 1: Run JumpServer locally

Goal: a working console at http://localhost in about 15 minutes.

Step 1. Check your machine

# OS, CPU, memory, disk
cat /etc/os-release | head -2
nproc && free -h && df -h /
# Docker (skip if installed)
docker --version

Step 2. Install Docker if missing

curl -fsSL https://get.docker.com | sudo sh
sudo systemctl enable --now docker
sudo usermod -aG docker $USER   # log out and back in after this

Step 3. Run the official installer

curl -sSL https://github.com/jumpserver/jumpserver/releases/latest/download/quick_start.sh | sudo bash

This downloads the installer into /opt/jumpserver-installer-vX.Y.Z, creates the config, pulls images and starts the containers. Accept the defaults for a local test (built-in database and Redis).

Step 4. Start and check it

cd /opt/jumpserver-installer-*
sudo ./jmsctl.sh start
sudo ./jmsctl.sh status
sudo docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"

All containers should show Up or healthy. Wait 1 to 2 minutes after first start.

Step 5. Log in

  1. Open http://localhost (or the VM's IP address).
  2. Username admin, password ChangeMe.
  3. You are forced to set a new password. Use a long unique one and save it in a password manager.
  4. Go to System Settings → Security and turn on MFA for admins.

Step 6. Prove the full cycle once

  1. Console → Assets → Hosts → Create → Linux. Add a test VM with SSH and a test account.
  2. Console → Authorizations: allow your user to use that asset and account.
  3. Workbench → My Assets: connect via Web CLI and run:
whoami
hostname
date -Is
exit
  1. Open Audits → Sessions. Confirm the session, its replay and the commands are listed.
Local is done when you can see the recorded session and the four commands. Do not continue until this works.

Part 2: Deploy on a stage server

Goal: the same setup on a real server, reachable by your team, with real settings.

Step 1. Prepare the server

sudo apt update && sudo apt -y upgrade
sudo timedatectl set-timezone Asia/Kolkata
sudo hostnamectl set-hostname jms-stage
# Firewall: only what is needed
sudo ufw allow 22/tcp
sudo ufw allow 80,443/tcp
sudo ufw allow 2222/tcp
sudo ufw enable

Point a DNS name such as jms-stage.yourcompany.com to the server's IP.

Step 2. Install

Run the same installer as in Part 1.

curl -sSL https://github.com/jumpserver/jumpserver/releases/latest/download/quick_start.sh | sudo bash
cd /opt/jumpserver-installer-*
sudo ./jmsctl.sh start

Step 3. Review the config file

sudo nano /opt/jumpserver/config/config.txt
KeyWhat to do
SECRET_KEY, BOOTSTRAP_TOKENGenerated for you. Back them up. Losing them makes stored credentials unreadable.
DB_HOST, DB_PASSWORDBuilt-in MySQL is fine for stage. Set a strong password if you change it.
HTTP_PORT / HTTPS_PORTKeep 80 and 443.

Apply any change with sudo ./jmsctl.sh restart.

Step 4. Make the server reachable to your targets

# From the JumpServer host, test each target
nc -vz TARGET_PRIVATE_IP 22
nc -vz MONGO_PRIVATE_IP 27017

Prefer private IPs or a VPN. Only the JumpServer host should be allowed to SSH into targets.

Step 5. Repeat the setup

  1. Change the admin password and enable MFA.
  2. Create real users and groups. No shared logins.
  3. Create nodes: /Unisellergy/Staging, /Unisellergy/Production, /Unisellergy/Database.
  4. Add the staging VPS as a Linux asset with a restricted pamaccess account.
  5. Add the MongoDB host (Linux) and MongoDB instance (Database) as two separate assets.
  6. Create authorizations such as STAGE-DEVELOPERS and MONGODB-READONLY using specific accounts, not "all accounts".
  7. Test an allowed connection and a denied one, then check Audits.
Stage is done when a normal user connects through JumpServer, an unauthorized user is blocked, and both show in the audit logs.

Part 3: Go live on production

Same steps as stage, with HTTPS, external database, backups and lockdown.

Step 1. Size and place the server

Use a dedicated server with at least 4 cores, 8 GB RAM and a disk with room for recordings. Put it in the same private network as your VPS targets. Use a name like jms.yourcompany.com.

Step 2. Install with an external database (recommended)

Create a MySQL/MariaDB database and a Redis instance first. Then run the installer and enter their details when asked, or set them in config.txt:

DB_HOST=10.0.0.20
DB_PORT=3306
DB_USER=jumpserver
DB_PASSWORD=use-a-long-random-password
DB_NAME=jumpserver
REDIS_HOST=10.0.0.21
REDIS_PASSWORD=use-a-long-random-password
curl -sSL https://github.com/jumpserver/jumpserver/releases/latest/download/quick_start.sh | sudo bash
cd /opt/jumpserver-installer-*
sudo ./jmsctl.sh start

Step 3. Turn on HTTPS

Copy your real certificate and key (from your CA or Let's Encrypt) into the nginx cert folder, then enable HTTPS in the config.

sudo cp fullchain.pem /opt/jumpserver/config/nginx/cert/server.crt
sudo cp privkey.pem   /opt/jumpserver/config/nginx/cert/server.key
sudo chmod 600 /opt/jumpserver/config/nginx/cert/server.key

# in /opt/jumpserver/config/config.txt
HTTPS_PORT=443
SERVER_NAME=jms.yourcompany.com
# then
sudo ./jmsctl.sh restart

Open https://jms.yourcompany.com and check the lock icon. Use this URL as evidence, not a localhost URL.

Step 4. Harden it

  1. Change admin password, create named admins, then disable day-to-day use of the default admin.
  2. Enforce MFA for all users in System Settings → Security.
  3. Set session recording storage and retention in System Settings → Storage.
  4. Limit the firewall: 443 and 2222 from office/VPN IPs only if possible.
  5. On each target VPS, allow SSH only from the JumpServer IP. Keep an emergency access path until you have tested the JumpServer path.

Step 6. Back up before adding assets

sudo ./jmsctl.sh backup_db
sudo cp /opt/jumpserver/config/config.txt /safe/location/config.txt.bak
sudo tar czf jms-data-$(date +%F).tgz /opt/jumpserver/core/data

Store backups off the server. Test a restore on stage once.

Step 7. Add production assets and verify

  1. Add the production VPS, MongoDB host and MongoDB instance using the Stage steps.
  2. Authorize only approved ops staff with the restricted account.
  3. Run a test session, then check Audits → Sessions and Session Commands.
  4. Export logs as CSV for your evidence pack.
Do not say all access is controlled until you have checked direct SSH, direct MongoDB, service accounts and emergency access are restricted or logged.

Daily operations and fixes

Useful commands

cd /opt/jumpserver-installer-*
sudo ./jmsctl.sh status      # health of all containers
sudo ./jmsctl.sh restart     # apply config changes
sudo ./jmsctl.sh stop        # stop everything
sudo ./jmsctl.sh backup_db   # database backup
sudo ./jmsctl.sh upgrade     # take a backup first
sudo docker logs --tail 100 jms_core

Common problems

ProblemCheck
Page does not loadjmsctl.sh status; wait 2 minutes; check firewall for 80/443.
Port already in useAnother web server on 80/443. Stop it or change HTTP_PORT in config.txt.
Asset shows unreachablenc -vz IP 22 from the JumpServer host; check target firewall and key.
No session recordingCheck storage settings and disk space; run a fresh test session.
Certificate warningUse the full chain file and match SERVER_NAME to your domain.

Upgrade routine

  1. Back up database and config.txt.
  2. Upgrade stage first and run the test session.
  3. Upgrade production in a quiet window.

Check the official docs at jumpserver.com/docs for the latest version-specific notes before each install or upgrade.
